# خطة تنفيذ مشروع تعدد اللغات (عربي / إنجليزي) - Smart Agency

تم إعداد هذه الخطة بناءً على ملف التدقيق والتحليل (`SMART-AGENCY-AR-EN-FULL-LOCALIZATION-AUDIT-AND-IMPLEMENTATION-PLAN.md`). تتوزع الخطة على **6 مراحل رئيسية** لضمان تنفيذ آمن وتدريجي دون التأثير على عمل الموقع الحالي.

---

## المرحلة الأولى: توسيع قواعد البيانات والواجهة الخلفية (Backend & Schema)
تهدف هذه المرحلة إلى تعديل بنية قاعدة البيانات لاستيعاب المحتوى الإنجليزي بجانب العربي مع الحفاظ على استقرار النظام الحالي.

- [x] **إضافة الحقول الإنجليزية**: إضافة حقول المحتوى الإنجليزي (مثل `titleEn`, `descriptionEn` الخ) كحقول اختيارية في جميع الـ Models (About, Blog, Projects, Services, وغيرها).
- [x] **بيانات التواصل والنشرات البريدية**: إضافة حقل `locale` لنماذج (Leads) والنشرة البريدية لمعرفة لغة التقديم، دون ترجمة أو تكرار بيانات المستخدمين.
- [x] **تحويل النصوص لرموز (Codes)**: تحويل القيم النصية في قاعدة البيانات (مثل "نعم/لا" أو أسماء التصنيفات في نموذج طلب عرض السعر) إلى قيم منطقية (Booleans) أو رموز ثابتة (Machine codes مثل `ios`, `android`).
- [x] **تحديث DTOs**: تحديث أنواع TypeScript والـ Validation (DTOs) لاستيعاب الحقول الجديدة بنفس شروط الحقول العربية.
- [x] **الحفاظ على التوافقية**: التأكد من أن جميع الـ Endpoints الحالية تستمر في العمل كالمعتاد.

## المرحلة الثانية: تعديلات لوحة التحكم (Admin Panel)
تهدف هذه المرحلة إلى تمكين مديري المحتوى من إدخال وتعديل البيانات باللغتين بسهولة.

- [x] **تصميم النماذج (Forms)**: فصل الحقول المترجمة في تبويبات (Tabs) خاصة بكل لغة (العربية | الإنجليزية)، مع إبقاء الحقول المشتركة (الصور، التواريخ، الأرقام) خارج التبويبات ليتم تعديلها مرة واحدة.
- [x] **مؤشر اكتمال الترجمة**: إضافة مؤشرات بصرية في واجهة لوحة التحكم تبين ما إذا كان العنصر مترجماً بالكامل أو ينقصه المحتوى الإنجليزي (مثال: `AR ✓ | EN Missing`).
- [x] **محرر النصوص (Rich Text Editor)**: تعديل محرر النصوص ليتوافق اتجاهه (RTL أو LTR) مع اللغة المحددة أثناء الكتابة.
- [x] **دعم الحفظ باللغتين**: تحديث دوال الإنشاء والتعديل في لوحة التحكم لإرسال واستقبال بيانات اللغتين معاً.

## المرحلة الثالثة: ترحيل المحتوى الحالي (Data Migration)
تُعنى هذه المرحلة بنقل المحتوى الإنجليزي المُجهز مسبقاً إلى قاعدة البيانات، مع تصحيح بعض الأخطاء في البيانات.

- [ ] **نسخ احتياطي**: أخذ نسخة احتياطية كاملة من قاعدة بيانات MongoDB قبل أي إجراء.
- [ ] **إدراج الترجمات**: استيراد الترجمات الإنجليزية المقترحة في التقرير إلى الحقول الجديدة الخاصة بها (`*En`).
- [ ] **تصحيح بيانات الجودة (Quality Issues)**: 
    - تصليح نص مشروع Tajaddod وتصحيح العبارات المكتوبة بشكل خاطئ.
    - تعديل الرمز التصنيفي `ٍSaaS` إلى `saas`.
    - تصحيح اسم التكنولوجيا `Garfana` إلى `Grafana`.
- [ ] **البيانات الحسابية**: حساب أوقات القراءة (Reading Time) للمقالات المترجمة بناءً على المحتوى الإنجليزي.

## المرحلة الرابعة: الـ API العامة وتعدد اللغات (Locale-aware Public API)
تهدف هذه المرحلة إلى تعديل الطلبات العامة للموقع لتقديم محتوى متوافق مع لغة المستخدم.

- [ ] **معامل اللغة (`lang`)**: إضافة استدعاءات للمتغير `?lang=en` أو `?lang=ar` في مسارات الـ API.
- [ ] **استجابات الـ API (Serializers)**: إرجاع المحتوى بصيغة موحدة (Localized) للموقع (مثلاً إرجاع الحقل `titleEn` كـ `title` في حال كانت اللغة المطلوبة إنجليزية).
- [ ] **سياسة اللغات البديلة (Fallback)**: عرض المحتوى العربي في حال كان المحتوى الإنجليزي فارغاً، لتجنب الصفحات الفارغة خلال فترة الإطلاق.
- [ ] **نظام البحث**: تحديث محرك البحث وتصفية البيانات ليشمل الحقول الإنجليزية في المدونات والمشاريع والخدمات.
- [ ] **ذاكرة التخزين المؤقت (Caching)**: عزل استجابات الـ API بالاعتماد على اللغة في مفاتيح الكاش لتجنب التداخل.

## المرحلة الخامسة: مسارات الموقع وواجهة المستخدم (Frontend Routes & i18n)
هذه المرحلة تركز على واجهة الموقع العامة وتطبيق التبديل الفعلي للغات.

- [ ] **إعداد مكتبة `i18next`**: تركيب وتفعيل مكتبة i18next و react-i18next ونقل 444 نصاً ثابتاً (Hard-coded) في الموقع إلى ملفات الترجمة `.json`.
- [ ] **إعداد المسارات (Routing)**: تغيير الروابط لتشمل اللغة مثل `/ar/about` و `/en/about` مع بقاء الروابط القديمة محولة (Redirect) للغة الافتراضية (العربية).
- [ ] **مبدل اللغة (Language Switcher)**: إضافة زر تبديل اللغة في القائمة العلوية للهواتف والحواسيب.
- [ ] **اتجاه الصفحة (Direction)**: استبدال قيم `dir="rtl"` الثابتة داخل الـ Components بمتغير ديناميكي يعتمد على مسار اللغة الحالي، واستخدام خصائص CSS المنطقية (Logical properties).
- [ ] **React Query**: تحديث مفاتيح الجلب (`queryKey`) لتتضمن اللغة الحالية، ليتم إعادة جلب المحتوى عند تغيير اللغة.

## المرحلة السادسة: الـ SEO، اختبار الجودة، الإطلاق النهائي (SEO & QA)
تأكد من أن الموقع يعمل بشكل مثالي في اللغتين ومهيأ لمحركات البحث.

- [ ] **تحديث الـ Meta Data**: إضافة ترجمات ديناميكية للعناوين (`<title>`) والوصف، وإضافة وسوم `hreflang` و `canonical` لكل لغة.
- [ ] **خريطة الموقع (Sitemap)**: توليد ملف sitemap يحتوي على روابط الموقع لكلا اللغتين بناءً على الروابط الجديدة.
- [ ] **اختبار الجودة البصري (Visual QA)**: التحقق من خلو الواجهة الإنجليزية من أي تداخل للاتجاه (LTR/RTL) والتأكد من توافق تصميم الجوال والشاشات.
- [ ] **اختبار الروابط والوظائف**: التأكد من أن الانتقال بين اللغات يحافظ على نفس الصفحة الحالية دون مشاكل.
- [ ] **تنظيف الكود (Cleanup)**: إزالة ملفات المحتوى القديم من مجلد `frontend/src/data` (بعد التأكد من عدم استخدامها).
- [ ] **قاعدة النشر**: تفعيل قواعد النشر في لوحة التحكم بحيث تمنع نشر أي محتوى مستقبلي مخصص للنسخة الإنجليزية دون استكمال حقوله الضرورية.
